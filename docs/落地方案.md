# 落地方案（目标机器实施蓝图）

> 本项目是研究/计划仓库，实际部署在**目标机器**执行（需 Unix 环境）。

---

## 硬性前置

- **环境**：Linux / macOS，或 **Windows + WSL2**；`tmux ≥ 3.3`、`uv`、`python ≥ 3.11`。
- **棋子安装**：`codex` / `claude`(Claude Code) / `opencode` / `hermes` 各自装好并完成**原生登录/鉴权**（BYOK 自带 key/订阅）。

---

## 里程碑

### M1：部署骨架
```bash
git clone https://github.com/awslabs/cli-agent-orchestrator.git
cd cli-agent-orchestrator
make setup        # uv 装依赖
```

### M2：初始化调度服务
```bash
uv run cao-server          # 编排服务（docs/api.md）
```

### M3：装配「董事长舰队」
- 用 `code_supervisor` 作首席（负责拆解+并行派活+归集）。
- supervisor 所在 provider 可自由选（Claude Code 或 Codex），下层 worker 可混搭不同 provider/模型 → **模型中立**。
- 装各队友 profile：
  ```bash
  cao install <developer>.md --provider codex_cli
  cao install <reviewer>.md  --provider opencode_cli   # 示例，见 docs/
  ```

### M4：董事长使用流程（你的画像）
1. **董事长**：`cao launch --agents code_supervisor`，输入一句战略目标。
2. supervisor 自动拆任务 → `assign` 并行派给多 worker（各自隔离 worktree/tmux 会话）。
3. writer 产出 → supervisor `handoff` 给 reviewer 评审 → 归集完整结果。
4. **董事长**：在审批门/看板审阅汇总，**签字通过或打回**；不写指令、不审 diff、不点运行。

### M5（中期，可选）：接入 OpenClaw / Z Code
- 探索 ACP（Agent Client Protocol）或 MCP wrapper 把 OpenClaw / Z Code 封装成 worker 接入 supervisor。
- 或暂不接入，维持四枚舰队。

## 风险与备选

| 风险 | 说明 | 缓解 |
|---|---|---|
| OpenClaw 非一等 provider | 自成体系，需自定义桥接 | 中期以 MCP/ACP 桥接，不阻塞主线 |
| 环境依赖 | 需 tmux + Unix | 使用 WSL2 |
| 安全 | 自动化默认走 `--yolo`/`--dangerously-skip-permissions` 绕过审批弹窗 | 落实 `tool-restrictions` / allowlist 收窄权限 |
| 骨架版本抖动 | v2.4.1 迭代快 | 上线前锁定 commit |
| 备选编排器 | bernstein(40+CLI含Gemini,887★) / paseo / Untrivial | 若 awslabs 不满足特定需求再切换 |
