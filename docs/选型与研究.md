# 选型与研究

## 研究范围

在「开源 + 模型中立 + 真·AI指挥AI编程 + 上层只发战略目标」交叉点上调研开源项目。
核心判断标准（两个分水岭）：
1. **模型中立**：是否兼容 Claude/GPT/Gemini/GLM/本地 Ollama，不锁厂商。
2. **真·编排外部 coding agent**：是否 spawn 子进程驱动 Codex CLI / Claude Code / OpenHands 等现有 CLI 并行干活，
   还是"框架自己写代码"（这一类**不符合**本需求）。

---

## 最终选型：`awslabs/cli-agent-orchestrator`

### 获胜理由（已源码级验证，非猜测）
1. **棋子覆盖（决定性）**——provider 枚举（`models/provider.py`）逐一核验：

   | 棋子 | awslabs 支持 | 实现 |
   |---|---|---|
   | Claude Code | ✅ 一等 | `providers/claude_code.py` |
   | Codex | ✅ 一等 | `providers/codex.py` |
   | OpenCode | ✅ 一等 | `providers/opencode_cli.py` |
   | Hermes | ✅ 一等 | `providers/hermes.py` |
   | OpenClaw | ⚠️ 非一等 | 需自定义桥接 |
   | Gemini CLI | 不在枚举 | 你不要，无影响 |

2. **"董事长只签不拆"成立**：
   - 内置 `code_supervisor`：NEVER write code yourself; ALWAYS assign; always handoff for review.
   - MCP 工具 `assign`/`handoff`/`send_message` 自动拆解 + 并行派活（可开隔离 git worktree）。
   - `handoff` 取回完整结果归集 → 供董事长审阅。
   - 工作流带**人工审批门**（用户批准才 run）——即"审批单签字"。

3. **无营销水分**：AWS 官方实验室，机制经源码阅读核验，git 原生。

## 为什么不是 OpenHands

| 维度 | OpenHands | 你的画像 |
|---|---|---|
| 形态 | 超级单兵 agent | 舰队指挥 |
| 并行 | 一 agent 全流程 | 多 worker 独立并行 |
| 审批签字 | 弱 | 你只签字 |
→ OpenHands 适合"丢给超级 agent"，不适合"舰队指挥 + 独立并行"。
