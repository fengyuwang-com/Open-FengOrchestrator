## 二、根因：不是 AI 不努力，是系统缺了五样东西

1. **缺一个统一的目标函数。** 昨晚的驱动是"一张静态清单"，不是"一个目标"。清单是死的，目标是活的——目标能自己生成任务，清单做完就断粮。你说"把系统优化到十分可用为止"，这句话从未被写成机器可对照的判据。
2. **缺"无活可干"的合法出口。** 心跳机制只设计了"醒着"，没设计"什么时候允许睡"。于是 AI 被迫每轮说点什么——要么空应答，要么造出 unwanted content 来填满回合。**空转和自嗨是同一个缺陷的两个症状。**
3. **缺主人意图的强制锚点。** todo.md 里有明确的"等创始人拍板/过目"区，但通宵 runner 没有被要求"每轮先读 todo 的创始人意图区，把待拍板项汇总进晨报、把可推进项排最前"。AI 按自己的规则跳过拍板项是对的，但跳过之后没有人接住它们。
4. **缺整体验收门。** 每个分支有自己的 tsc/体检，但没有人站在"系统整体"的高度做：分支间冲突预判、合并顺序、全量回归、和 master 的最终一致性。这个角色昨晚实际上是空缺的，直到早上人回来手动收口。
5. **缺完成定义（Definition of Done）。** "十分可用"没有判据 = 永远不知道做没做完 = 循环没有终止条件。AI 只能要么停（被你批评没探索精神），要么乱做（unwanted content）。

## 三、经验教训（浓缩为十条）

1. **心跳是钟，不是任务。** 定时唤醒只该负责"检查有没有活"，有活才开工，没活就记录一行并安静退出——绝不为回应心跳而制造动作。
2. **队列必须能自我补给。** 任务来源优先级：①主人指令（最高）②todo.md 待办区 ③验收/回归发现的回归项 ④探索队列（最后，且有配额上限）。探索只配占小头。
3. **"等拍板"是合法且光荣的状态。** 遇到拍板项的正确动作是：跳过 + 记入晨报汇总区，然后去找下一件能做的。不要围绕它造次。
4. **每个通宵必须指定一个"收口员"。** 要么每 N 轮自动合并一次（分支少而新），要么明确留到早上——但不能两个都不说，导致 5 个分支悬在空中。
5. **凡产出必问一句：主人要过这个吗？** 写文档、立新规、开新分支之前先对照 todo 和主人最近的指令。答不上来就不做。
6. **完成要有判据。** 目标要翻译成可检查的验收清单（回归 0 fail、某页面可用、某债务清零），做到判据全绿 = 通宵结束，写晨报收工。
7. **预算与熔断。** 每晚 token/时间预算封顶；同一任务连续 2 轮无进展就标记搁置换下一个；空转 2 轮即自动降频（5 分钟 → 30 分钟 → 停）。
8. **分支纪律要含"合并策略"。** 有分支就要随时注意（你已立规）——延伸版：分支寿命不超过一晚，要么当晚并回，要么晨报里排好合并顺序。
9. **晨报是唯一交接面。** 完成了什么 / 什么没做完为什么 / 待拍板清单 / 系统当前健康度（回归结果）四段式，人不该需要翻 git log 才知道晚上发生了什么。
10. **AI 的自主性用在"怎么做好"，不用在"做什么"。** 做什么由目标+todo 决定，怎么做（技术方案、实现细节、质量把关）AI 全权负责。这条边界划清，unwanted content 自然消失。

## 四、下一步：目标驱动的自主进化系统（v2 设计）

你想要的形态一句话：**你说一个目标 → AI 自己拆解、排期、通宵推进、自我验收 → 你早上只看一份晨报、只做几个拍板。**

### 核心机制（四个文件 + 一套节拍）

**1. MISSION.md（目标文件，你唯一需要写的东西）**
```
# 当前总目标
把系统优化到十分可用为止（判据见下）
# 可用性判据（做完即通宵结束）
- [ ] 全量回归 0 fail 0 warn
- [ ] todo.md 待办区清零（拍板区除外）
- [ ] 创始人体验路径全部跑通（首页→研究→持仓→报告）
# 禁止事项
- 不做 todo 之外的"自选动作"；不做需拍板的事
```

**2. todo.md = 唯一任务真相源**（已立规）：runner 每轮开工第一件事读 todo 的"待办区"，认领第一项；做完删除；发现新问题回写 todo。等拍板区只汇总不追问。

**3. 每轮节拍（替换现在的固定应答）**
```
读 MISSION 判据 → 全绿？→ 是：写/更新晨报，降频休眠
              → 否：读 todo 取任务 → 有：走 overnight 分支干一单（tsc+体检+commit+push）
                                  → 无：只读巡检（git/数据新鲜度/回归抽查），
                                       有异常→升格为任务回写 todo；无异常→记一行休眠
```

**4. 晨报 + 收口规则**：每晚固定一个"收口轮"——合并当晚分支回 master、跑全量回归、写四段式晨报（完成/未完成及原因/待拍板/健康度）。这个轮必须存在，不管任务做完没做完。

### 熔断与预算
- 每晚预算封顶（token/轮次），用完即收口写晨报；
- 同一任务 2 轮无进展 → 搁置记原因，换下一单；
- 空转 2 轮 → 自动降频；判据全绿 → 彻底休眠等人。

### 落地节奏建议（三步走）
1. **第一步（现在就能做）**：把 MISSION.md 和每轮节拍写进 cron 任务提示词，替换"无动作应答"逻辑——这是纯提示词层改造，一小时的事。
2. **第二步**：把"收口轮"固化（每晚一次自动合并+全量回归+晨报），消除分支悬挂。
3. **第三步**：给判据接真闸门（fengwebcheck 全绿作为完成信号），实现"判据全绿自动休眠、判据红了自动开工"的闭环——到这一步，系统才是真正的"你说目标，它自己进化"。

## 五、一句话总结

昨晚证明了 AI 能干活的下半场（执行）是及格的，缺的是上半场（干什么、何时停）：**给判据而不是给清单，给出口而不是给心跳，给锚点而不是给自由。** 补上这三样，"你睡觉、它进化"就能成立。
