# 部署与使用方案（董事长视角）

> 本文件把「选型与研究」和「落地方案」的结论，翻译成**董事长（只发目标 + 签字）**能看懂的使用蓝图，
> 并记录本机实况、首期迭代路径与成本决策。

---

## 一、角色图解（用小孩的话说）

想象一所学校的**大队部**：

```
你(校长/董事长) —— 只干两件事：①发一句目标  ② 在审批单上签字/打回
        │
        │  ZCode = 你的秘书(传话筒)：把中文翻译成行话，把审批结果读回来给你点
        ▼
办公室主任(code_supervisor CEO) —— 不自己写作业，负责：拆任务 → 派活 → 收作业
        │
        │  awslabs 调度器 = "会议室/分派小本本"：开 N 个独立小房间(tmux/worktree)，记录谁在干啥
        ▼
  干事们(Claude Code / Codex / OpenCode / Hermes) —— 真正动手写代码，各用各的笔纸(key/模型)
```

- **董事长永远不直接跟"干事"说话**，也不碰任何 key——那是办公室主任的事。
- **awslabs 不碰 API key**：它只负责把任务在独立会话里并行调度，核销由各干事自己的 key/订阅完成（相当于董事会不代管高管差旅，各高管自己刷卡）。

### 董事长的两个"指挥"手势
1. **下命令**：ZCode 把一句中文目标，翻译成办公室主任(command)能懂的 launch/目标。
2. **签字**：办公室主任派完活、归集结果后，挂出**审批门**，你在看板上点「通过」或「打回」。批准才 run。

## 二、关键判断（本仓库选型确认）

| 问题 | 结论 |
|---|---|
| 架构可行吗 | ✅ 可行。`awslabs/cli-agent-orchestrator` 是目前"开源+模型中立+指挥外部CLI"最佳解。 |
| 能用 1 个 key 跑多个同一工具吗 | ✅ 可以，且是设计本意。awslabs 不校验 key，provider 只发 `opencode --agent X`，认证下放给工具自身 → 同一份 key 天然被 N 实例复用（官方 `examples/assign/` 即 3 实例并行）。各 worker 可用 `--model` 指定不同模型(模型中立)。 |
| 单 key 多实例的坑 | ⚠️ 所有实例共享 `~/.config/opencode/opencode.json`，并发写会竞态（官方 docs 自述）。缓解：隔离 HOME + symlink 复用 key。未查到"同 key 多实例触发限流/封号"实证。 |
| 全用 OpenCode 的意义/局限 | 省钱（1份 key，不用4份订阅）但牺牲交叉评审（四个同模型≈四个克隆人）。评审价值要靠"不同模型"找回。 |

## 三、本机实况（2026-08-15 核查）

| 棋子 | 状态 | 判定 |
|---|---|---|
| **Hermes v0.18.2** | ✅ 完整可用（`AppData\Local\hermes`），可配 OpenCode Zen/go | **唯一现成可用棋子**，优先用它首期试跑 |
| opencode | ⚠️ shim 在、`opencode.exe` 缺失，但 `~/.config/opencode/` 配置+key 完好 | 二进制坏了，配置资产可复用 |
| codex | ❌ `codex.js/.exe` 缺失、`auth.json` 空（`~/.codex` 只剩 sqlite/残留） | 基本失效 |
| claude (Claude Code) | ❌ 未安装 | 无 |

- **结论**：本机"装的太多/好坏"其实是"能用的几乎只有 Hermes"。务实路径是**先用 Hermes，不新增安装**（贴合"少装不折腾"）。
- **Hermes 模型源**：用户将 Hermes 结算指向 **OpenCode Zen / go**（`https://opencode.ai/zen/go/v1`，原生 OpenAI 格式），与 codex/opencode 同一生态。

## 四、首期迭代（M0：先用 Hermes 验证手感）

> 目标：零安装，先把「董事长→CEO→干事→归集→签字」真跑通，验证值不值得，再决定扩舰队。

1. Hermes 配置为 OpenCode Zen/go + key（写进 `AppData\Local\hermes\config.yaml` 或 `.env`，密钥不入库）。
2. 用一个真实小任务试跑：发一句目标 → 观察拆解/执行/归集。
3. 由 ZCode 做「秘书层」：中文目标 → Hermes 调用 → 结果回读 → 生成审批单供签字。

**通过判据**：一次目标能产出可交付结果，且你只做了"发目标+签字"两个动作。

### 首期试跑记录（2026-08-15 已验证）

- **预备**：将 Hermes 的 `AppData\Local\hermes\config.yaml` 模型段改为
  `provider: custom`、`base_url: https://opencode.ai/zen/go/v1`（OpenCode Zen/OpenAI 原生格式）、`default: deepseek-v4-flash`。
  修改前已备份 `config.yaml.bak-uri-*`。
- **实证**：Hermes 通过 Zen 端点点直接跑通 —— 在空工作区生成 `hello_worker.py`、
  运行并用 `assert 6*7==42` 校验、返回任务完成汇总，全程走深/OPencode Zen 的 `deepseek-v4-flash` 模型。
- **结论**：单干事"发目标→执行→写盘→归集"链路成立；Hermes 作为 OpenCode Zen 网关的 worker，模型中立，
  一个 key 可在 `/v1/models` 换 minimax/kimi/glm/deepseek 等模型。

### 后续（M1+，可选）
- 修复/补装一枚 opencode，用其现有 Zen key 扩到多实例（1key×N）。
- 或维持 Hermes 单干事，需要时再议。
- 内网镜像远程地址确认后：`git remote add mirror <url>` 双远程同步。

## 五、安全与成本备注
- **审批门收窄权限**：默认 `--yolo`/`--dangerously-skip-permissions` 会绕过审批，部署时用 `tool-restrictions`/allowlist 收窄。
- **成本**：多干事并行 = 多倍 token。首期用单 Hermes 控成本；扩舰队后再评估 1key×N 是否合算。
- **密钥纪律**：API key 绝不入 git（`FENGMEM.md`/本文件仅记"指向哪个服务"，不含明文）。
